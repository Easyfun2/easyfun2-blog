用 GitHub Pages 搭一个自己的主页

个人主页最容易被「技术选型」拖住：要不要上框架？要不要买服务器？要不要配域名？ 这次我选择最笨也最稳的办法——纯静态文件 + GitHub Pages。

三步走

  1. 在 GitHub 新建一个公开仓库；
  2. 把 index.html、样式和脚本推上去；
  3. 仓库 Settings → Pages → Source 选 main 分支根目录，保存。

几分钟后就能通过 https://<用户名>.github.io/<仓库名>/ 访问了。 如果仓库名就是 <用户名>.github.io，地址会更短。

几个实践建议

  • 加一个 .nojekyll 空文件，跳过 Jekyll 预处理，路径更可控；
  • 资源一律用相对路径，子目录页面也能正常加载；
  • 写文章就是新增一个 HTML 文件，然后在首页列表里加一行链接；
  • 自定义域名只需要在仓库里放一个 CNAME 文件，并在 DNS 加一条记录。

为什么不用生成器

Hexo、Hugo、Jekyll 都很好，但它们引入了一层构建：要装环境、要记得跑命令、构建失败还要排错。 个人站点内容不多时，这层构建的收益并不明显。

当然，文章多到几十篇以后，手工维护列表会累。到那时再迁移到生成器也不迟——内容和仓库都在，迁移成本很低。
